# ai-security-scanner

[English](README.md)

## 不必先學一堆工具，也能找出資安問題

`ai-security-scanner` 是為開發者、小型團隊與 IT 管理者設計的桌面掃描器，重點是提供有用的發現項目與清楚的下一步。

選擇你擁有或確定獲准評估的程式碼專案、內部系統、端點與網站。應用程式會執行適用的檢查，並把結果整理成一份報告，直接說明哪些資產需要處理。

## 最適合先掃什麼？

### 掃描一個 IT 環境

在同一個精簡設定中加入多個程式碼資料夾、完整網站或 API 網址，以及已獲准的內部系統。每個內部系統只需輸入一個精確主機名稱或 IP 位址；常見 TCP 連接埠已預設完成，需要時可在「進階」中改為最多 64 個精確連接埠。確認一份掃描計畫後，只按一次「開始」。

內部系統不再分成廠牌專用流程。應用程式會把精確的已獲准主機與連接埠交給固定版本的 Greenbone Community Feed 設定；Greenbone 自行辨識對外服務與產品、套用先決條件符合的上游遠端檢查，再回傳發現。網路設備、伺服器、工作站與其他使用 TCP 的系統都使用同一條上游驅動路徑。

預設設定不使用帳密、不擴大到鄰近主機、不嘗試預設密碼、不執行拒絕服務檢查，也不會進行需登入的本機修補盤點。零發現只表示 Greenbone 已完成對畫面所列連接埠的適用性掃描，且未回傳發現；不代表每個 feed 檢查都實際執行，也不代表整台設備安全。

如果只想檢查一個項目，可以使用相同掃描專案模型的快捷流程：

- **網站或 API。** 輸入一個精確的公開 `http://` 或 `https://` 網址。Nuclei 會辨識網站技術，並從固定上游快照中 4,674 個合格模板選用適用的唯讀弱點與暴露檢查。設定限制為每秒最多 10 次請求、同時最多 5 次，每次請求逾時 10 秒。

  掃描界線是整個 `scheme://host:port` 網站來源範圍，不只是在網址中輸入的路徑。路徑會保留作為參考，適用的上游模板可能請求同一來源範圍內的其他路徑。如果只獲准測試特定路徑，請勿使用此快速設定。它不會登入、送出表單或 request body、跟隨重新導向、使用站外回呼或執行利用型檢查，也不能取代滲透測試。因為 Nuclei 會依偵測到的技術選擇模板，完成不代表 4,674 個模板全部執行。

- **本機程式碼或 AI 專案。** 選擇一個專案資料夾。應用程式會掃描私密的唯讀副本，依適用情況找出危險程式碼模式、暴露的秘密、有弱點的相依套件與設定問題。

  `.env`、私鑰與 `*.tfvars` 等常見秘密檔案即使被 Git 忽略，仍會交給秘密掃描器；被忽略的相依套件、建置與快取目錄仍維持排除。應用程式不會上傳或修改專案、不會推送變更，也不會拿偵測到的憑證連線真實服務。

- **基礎設施內容或容器映像。** 選擇基礎設施即程式碼檔案、Kubernetes 設定檔或匯出的容器映像。應用程式會針對精確選定的內容，檢查適用的設定、套件與已知弱點。

  它不會部署基礎設施，也不會執行容器映像。即時雲端與叢集檢查屬於另一條進階流程，會使用各自的明確範圍。

需要時也可以加入受支援的雲端帳號、基礎設施內容與其他專業來源。

## 資產盤點與連線檢查都不等於弱點掃描

收合的 **測試本機服務連線 127.0.0.1:9001** 工具只會進行一次不傳送內容的 TCP 連線嘗試。它只會告訴你該連接埠是接受連線、拒絕連線或逾時。

這個快捷動作不會檢查弱點、HTTP 行為、其他連接埠或整台電腦。資產盤點、開放連接埠或有回應的服務可以幫助選擇後續檢查，但都不是弱點結果。同樣地，「可以連線」、「已關閉」與「沒有發現問題」都不代表安全；報告會列出真正執行過的檢查。

## 三個步驟開始使用

1. **安裝應用程式。** 從 [GitHub Releases](https://github.com/teddashh/ai-security-scanner/releases) 下載桌面安裝程式。
2. **建立掃描專案。** 加入想檢查的程式碼專案、網站與已獲准的精確內部主機，或使用單一目標快捷流程。確認精確資產與連接埠後，只按一次「開始」。
3. **使用統一報告。** 每個已選資產會分別顯示「發現問題」、「已完成檢查未發現問題」、「未完成或失敗」或「尚未測試」。先處理需要注意的資產，並讓明列的限制跟著結果保留。

想得到最有用的第一份結果，請選擇你了解的真實資產並執行適用的資安檢查。只有在你確實要檢查連接埠是否能連線時，才打開收合的 localhost 工具。

## 怎麼看結果？

每份報告會回答這些實際問題：

- **我要求掃描什麼？** 選定的目標與限制。
- **實際測了什麼？** 已完成的檢查與目標範圍。
- **哪些沒有測到？** 失敗、無法使用、排除、逾時或取消的工作。
- **哪些資產有問題？** 依優先順序排列的問題、嚴重度、信心程度與受影響項目。
- **接下來怎麼做？** 有明確範圍的行動，以及需要時應找哪一類專家。

報告可能完整、部分完成，或沒有任何檢查完成。即使另一項檢查失敗，已完成的結果仍會保留。專案與報告可以重新開啟、和之後的掃描比較，也可以匯出成好讀的 HTML 或結構化資料。

## 資料與授權

專案、發現項目與證據會留在你的裝置上，除非你主動連接外部來源或匯出。應用程式不會自動修改掃描目標。

只能掃描你擁有或確定獲准評估的系統。案件資料依賴作業系統帳號與磁碟保護；應用程式本身不另外提供靜態資料加密。

## 瀏覽器預覽

瀏覽器預覽只用來查看介面。它使用清楚標示的範例資料，不會執行掃描器，也不會接觸任何目標。

```sh
npm ci
npm run dev
```

請開啟 Vite 顯示的本機網址。需要 Node.js 24 或更新版本。

## 開發

從原始碼開發需要 Node.js 24 或更新版本、Rust 1.98，以及桌面建置所需的 Tauri 平台相依套件。

```sh
npm ci
npm run typecheck
npm run test:frontend
npm run test:component
npm run build
cargo test --workspace --no-default-features --features cli
npm run tauri dev
```
