# ai-security-scanner

[English](README.md)

## 不必先學一堆工具，也能找出資安問題

`ai-security-scanner` 是為開發者、小型團隊與 IT 管理者設計的桌面掃描器，重點是提供有用的發現項目與清楚的下一步。

選擇你擁有或確定獲准評估的項目。應用程式會引導設定、執行適用的檢查，並把結果整理成一份容易理解的報告。

## 最適合先掃什麼？

### 網站或 API

輸入一個精確的公開 `http://` 或 `https://` 網址。新手流程會執行固定版本的 Nuclei 快速設定，以 13 項檢查尋找常見的暴露檔案，以及除錯或狀態端點。最多送出 19 次 GET 請求，每秒最多 3 次、同時最多 2 次，逾時為 10 秒。

掃描界線是整個 `scheme://host:port` 網站來源範圍，不只是在網址中輸入的路徑。路徑會保留作為參考，而快速設定會請求自己的固定偵測路徑。如果只獲准測試特定路徑，請勿使用此快速設定。它不會登入、不會送出表單、不會跟隨重新導向，也不會利用發現的弱點；它不能取代滲透測試。

### 本機程式碼或 AI 專案

選擇一個專案資料夾。應用程式會掃描私密的唯讀副本，依適用情況找出危險程式碼模式、暴露的秘密、有弱點的相依套件與設定問題。

它不會上傳或修改專案、不會推送變更，也不會拿偵測到的憑證連線真實服務。

### 基礎設施檔案或容器映像

選擇基礎設施即程式碼檔案、Kubernetes 設定檔或匯出的容器映像。應用程式會針對精確選定的內容，檢查適用的設定、套件與已知弱點。

它不會部署基礎設施，也不會執行容器映像。即時雲端與叢集檢查屬於另一條進階流程，會使用各自的明確範圍。

準備好定義精確範圍時，也可以檢查公開 IP、已獲准的內部網路與支援的雲端帳號。

## 連線檢查不等於弱點掃描

收合的 **測試本機服務連線 127.0.0.1:9001** 工具只會進行一次不傳送內容的 TCP 連線嘗試。它只會告訴你該連接埠是接受連線、拒絕連線或逾時。

這個快捷動作不會檢查弱點、HTTP 行為、其他連接埠或整台電腦。同樣地，「可以連線」、「已關閉」與「沒有發現問題」都不代表安全；報告會列出真正執行過的檢查。

## 三個步驟開始使用

1. **安裝應用程式。** 從 [GitHub Releases](https://github.com/teddashh/ai-security-scanner/releases) 下載桌面安裝程式。
2. **選擇並開始檢查。** 選擇網站、本機專案、設定檔案、映像、網路或帳號。確認精確目標與限制後，按下「開始」。
3. **使用報告。** 先看優先順序最高的問題，依照建議處理，並檢查這次沒有測到的項目。

想得到最有用的第一份結果，請掃描你了解的真實網站、專案或檔案。只有在你確實要檢查連接埠是否能連線時，才打開收合的 localhost 工具。

## 怎麼看結果？

每份報告會回答五個實際問題：

- **我要求掃描什麼？** 選定的目標與限制。
- **實際測了什麼？** 已完成的檢查與目標範圍。
- **哪些沒有測到？** 失敗、無法使用、排除、逾時或取消的工作。
- **發現了什麼？** 依優先順序排列的問題、嚴重度、信心程度與受影響項目。
- **接下來怎麼做？** 有明確範圍的行動，以及需要時應找哪一類專家。

報告可能完整、部分完成，或沒有任何檢查完成。即使另一項檢查失敗，已完成的結果仍會保留。專案與報告可以重新開啟、和之後的掃描比較，也可以匯出成好讀的 HTML 或結構化資料。

## 資料與授權

專案、發現項目與證據會留在你的裝置上，除非你主動連接外部來源或匯出。應用程式不會自動修改掃描目標。

只能掃描你擁有或確定獲准評估的系統。案件資料依賴作業系統帳號與磁碟保護；應用程式本身不另外提供靜態資料加密。

## 瀏覽器預覽

瀏覽器預覽只用來查看介面。它使用清楚標示的範例資料，不會執行掃描器，也不會接觸任何目標。

```sh
npm ci
npm run dev
```

請開啟 Vite 顯示的本機網址。需要 Node.js 24 或更新版本。

## 開發

從原始碼開發需要 Node.js 24 或更新版本、Rust 1.98，以及桌面建置所需的 Tauri 平台相依套件。

```sh
npm ci
npm run typecheck
npm run test:frontend
npm run test:component
npm run build
cargo test --workspace --no-default-features --features cli
npm run tauri dev
```
