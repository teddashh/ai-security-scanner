# v0.2.0 product-completion release

`v0.2.0` is the product-completion release line for the local-first assessment workflow. It keeps
existing cases and historical evidence intact while adding typed target intake, exact provider
scope, and immutable execution contracts across the required scanner families. A source checkout
or version string is not proof that the release shipped; publication still requires the exact-tag
platform builds, signed release evidence, and version-bound usability evidence described below.

## Typed local targets and durable evidence

- Repository, IaC, OCI image-layout, Kubernetes manifest, and node-configuration inputs use
  explicit input profiles instead of an ambiguous shared directory contract.
- The backend validates each selected target, creates a private immutable snapshot, records its
  digest and source identity, and gives an engine only the mount and profile declared by its plan.
- OCI layouts are checked as a closed, single-image graph with bounded manifests, configs, layers,
  tar entries, uncompressed bytes, and exact diff IDs before Trivy or Grype receives them.
- Coverage and case exports retain raw evidence, adapter and engine provenance, completeness
  issues, and the distinction between a completed empty check, unknown scope, partial capture, and
  a passing result.

## Exact provider scope

- AWS Organizations discovery is bound to one Organizations-enabled caller source. Each scanner
  execution still requires an exact short-lived caller identity for the selected AWS account;
  organization enumeration alone never authorizes a member account.
- Azure discovery and execution are bound to one exact tenant and an `Enabled` subscription.
- Google Cloud discovery walks the bounded active folder/project hierarchy under one exact
  organization, then splits approved scope into one exact active project per execution.
- The managed Prowler wrapper exposes separate AWS-account, Azure-subscription, and GCP-project
  profiles with provider-specific identity preflight and fixed endpoint closure. CloudQuery,
  Steampipe, ScoutSuite, and Cloudsplaining remain AWS-only; upstream feature names do not widen
  their released scope.
- Microsoft 365 remains one exact tenant per source and execution capability. Bootstrap credentials
  never enter scanner containers.

## Required engine integration

- The required 21-engine catalog binds every runnable engine to an immutable image digest,
  launcher profile, adapter, evidence path, coverage behavior, license disposition, and
  verification path. Scanner images remain separate artifacts and are not bundled in desktop
  installers.
- Managed images publish Linux AMD64 and ARM64 indexes with platform-specific SBOM and provenance
  evidence. Gitleaks and KICS remain explicitly verified upstream-image exceptions.
- Trivy's fixed offline profiles cover recognized language-package manifests in repository and IaC
  working trees, including supported Java manifests such as `pom.xml`, and recognized OS packages
  in validated OCI layouts. Dependencies discoverable only from JAR contents stay excluded; Grype
  supplies the complementary offline OS/language-package and JAR archive path for OCI images.

## One-click Windows setup

- When WSL 2 is missing, disabled, or outdated, the app offers one primary **Fix this for me**
  action instead of requiring an Administrator PowerShell walkthrough.
- Windows shows its normal administrator confirmation once. The backend runs only the trusted
  `System32\wsl.exe` operation fixed for the current failed prerequisite; it accepts no command or
  arguments from the UI and never sees the administrator password.
- Setup automatically checks Windows again and continues. A required Windows restart is shown as
  the sole next step and is never triggered automatically. Manual Microsoft commands remain under
  a secondary **Other ways** disclosure.

## Upgrade and qualification

Existing local cases, cleanup obligations, evidence snapshots, and provenance are retained across
the application update. Baseline comparisons remain conservative whenever engine, adapter,
ruleset, input, or completeness provenance is not comparable.

The release workflow rebuilds and installs Linux x86-64, universal macOS, and Windows x86-64
packages from the exact tag, verifies updater signatures and complete checksums, and publishes
build-provenance attestations. Fresh hosted qualification jobs on Ubuntu 24.04, macOS 15 Intel,
and Windows 2025 must each complete managed-runtime install, real machine start, the fixed
network-disabled Gitleaks container probe, stop, purge, and private-state cleanup; skipped or
host-limited macOS evidence is rejected. Product completion additionally requires the
version-bound observed first-run study with a qualifying IAM-naive participant; automated or
maintainer-only walkthroughs do not satisfy that requirement.

Linux qualification additionally proves that the manifest-bound real QEMU exposes the exact
`vhost-user-fs-pci` device needed by the managed VirtioFS application-data mount. Windows proves
the complete fixed Podman WSL namespace has protected current-user-only ownership before the first
provider command. All managed Podman preflights parse the pinned `Host.Security` schema and require
rootless seccomp isolation.

Apple Developer ID, Apple notarization, and Windows Authenticode are not configured, so operating
systems may show an unidentified-developer warning. Updater signatures, checksums, SBOMs, and
GitHub attestations verify the published bytes but do not substitute for those OS trust systems.
