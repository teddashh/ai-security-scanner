# v0.1.8 automatic Windows workspace recovery pre-release

`v0.1.8` removes the manual WSL cleanup step shown during first launch when
ai-security-scanner can prove that the old scan-tool workspace belongs to this product.

## What feels different

- First launch explains that it is finishing an earlier setup and shows live progress in English
  or Traditional Chinese.
- A verified product-owned workspace is preserved, replaced, and restarted automatically.
- If setup is interrupted, the app resumes from durable recovery records instead of asking the
  user to repeat the whole process.
- Manual Windows instructions remain only for a workspace whose ownership cannot be proven. The
  app does not remove that workspace.

## Recovery transaction

Before replacing anything, the app uniquely binds the WSL distribution to a verified installed
ai-security-scanner manifest and its private storage. It checks free space, terminates that exact
distribution, performs a full file proof, exports a tar recovery archive, synchronizes it to disk,
and records its size and SHA-256. The archive is imported under a generated isolated distribution
name and verified against Windows' registration and storage state.

Only after the archive, imported recovery workspace, and unchanged original registration have all
been reverified may the old distribution be unregistered. The replacement runtime is then created,
started, and required to become ready before the temporary bootable recovery distribution is
removed. The opaque archive and bounded recovery records remain available for diagnosis. Cleanup
and retry paths are idempotent across process or machine interruption.

The recovery phase does not broaden scan scope, approve a target, or contact a scan target.

## Release qualification

The recovery state machine has Rust regression coverage for first attempt, interrupted import,
interrupted replacement, durable retry, exact cleanup, and direct-unregister authorization. The
frontend has bilingual progress and fallback coverage. The Windows production and test code paths
are compiled with warnings denied.

Fresh Linux and Windows installer jobs exercise the managed runtime, fixed private gateway, and
network-disabled Gitleaks container probe. The fixed gateway probe exchanges only a SOCKS greeting
and never sends CONNECT. Windows MSI and Windows NSIS Setup are qualified independently.

The macOS 15 Intel job verifies the installed app, its companion executables, and packaged runtime
manifest. Its managed-runtime lifecycle and network-disabled Gitleaks container probe are recorded
as `not_observed`, not passed because the hosted environment does not provide the nested
virtualization required by AppleHV. This limited evidence is accepted only for a pre-release.

Apple Developer ID signing, notarization, and Windows Authenticode are not configured for this
preview, so the operating system may show an unidentified-developer warning. Updater payloads use
the separate release signing key and must pass the checked-in integrity and provenance workflow.
