## 這輪實際找到並修掉的問題

### 1. 網站專案建立後變成 0 items

- 根因在 browser preview persistence，不在 Coverage checkbox。
- `knownAssets` 已被 local storage 保存，但 `getDemoSnapshot()` 對新 case 固定產生空 workspace。
- 修復後會投影一個 `user_declared` source、穩定 asset identity 與 asset-level coverage。
- `example.com` 保留為 exact `dns_name`，HTTPS／443／path `/` 保留為 preset；preset 不等於授權。
- 所有候選仍為 `pending`、`discovered_not_authorized`、`allowedModes: []`、`scanAttempted: false`，且沒有 grant、run、finding 或 export。
- loopback／private／sensitive target 即使 storage 標為 public 仍強制 internal；缺少 exposure 則保持 unknown，不替使用者猜 public。
- malformed browser payload 整批 fail closed，不會產生可掃描或已授權資產。

### 2. 核心 Start 被完成步驟推到首屏以下

- 實際 screenshot 顯示 Add inputs 與 Review items 佔滿首屏，真正的確認與 Start 需要往下找。
- 單一 guided network／website 或完成的 local-copy 路徑，現在預設只顯示 `Review and start`。
- 首屏保留 exact target／copy、必要限制、禁止事項、唯一 Advanced 與唯一 Start。
- `Edit inputs` 可展開完整 Step 1／2；`Back to review` 可回到聚焦狀態。
- Cloud provider panel 仍維持掛載，避免把已驗證的 provider connection 因收合而清掉。

### 3. 精簡不能吃掉誠實揭露

- 將「可以免第二次 ownership form」與「可以壓縮 UI」拆成不同判斷。
- Public-record 模式仍直接顯示 exact target、asset、scope chooser 與重要限制：本版沒有 check 會在 scan 中讀 public records，所以該 permission 本身不增加實際測試內容。
- Network／local／cloud 的精簡路徑仍保留各自的 always-visible boundary。

### 4. 新掃描與 preview 回饋

- New scan 表單打開時隱藏 current project、project list 與 workflow 說明，只留下名稱、第一個 target、必要安全提示與收合的 optional details。
- 尚未有 run 時，不再顯示 `Problems found 0` 或 `Systems found 0` 這種容易被解讀為掃描結果的數字。
- Browser preview 不顯示無效的 Refresh。
- Preview banner 精簡為 `Preview only · No target is contacted.`。
- Preview 中點 Start 會明確顯示 `Preview only — no scan ran` 與 `No target was contacted`，不再給「再試一次」的錯誤暗示。

## E2E UI／UX 實際走查

使用最新 source 的 browser dev surface 實際操作，不只讀 source：

1. 開啟 New scan，選擇 deployed website 路徑。
2. 建立 `Concise UI demo E2E`，輸入 `https://example.com` 並 submit。
3. Reload 後重新選取該 browser-saved project，確認 case phase 為 `Confirming scope`。
4. 進入 Coverage，確認 `Items found 1`，唯一候選為 exact `example.com`，並自動選取 conservative low-impact preset。
5. 確認首屏只保留：`Confirm example.com`、`Public website`、HTTPS 443、25/s、10 concurrent、3s timeout、禁止事項、一個 Advanced 與一個 Start。
6. 展開 Advanced，確認 target 與 port 仍是 `example.com`／`443`；沒有第二份 scan-type panel、ownership checkbox、note form、selected chips 或 dead Refresh。
7. 點 `Edit inputs`，確認 Step 1／2 可恢復；點 `Back to review`，確認可回到單一核心畫面。
8. 點 `Confirm and start scan`；preview 明確拒絕執行並回報沒有 scan、沒有接觸 target。

這證明了 browser source 的核心 UI state transition 與資料持久化，不是 Windows installed-candidate 的真實掃描證據。本輪沒有把 browser preview 冒充 native E2E，也沒有接觸 `example.com` 或 `127.0.0.1:9001`。
