# v0.1.9 Windows WL-13 桌面 Codex 交接

這份 handoff 只執行 `WL-13/runtime_reconciliation`：讓精確、已審查的 Windows host fixture 只監聽 `127.0.0.1:9001`，再從真正安裝的 v0.1.9 desktop 完成 localhost quick task、保存報告、重開專案並匯出 HTML。它不建立其他 lifecycle initial state，也不授權操作 WSL、Registry、Docker、Podman 或產品資料。

WL-13 tooling 是發佈後的外部 qualification 工具，不是 v0.1.9 product binary。它不會改寫已發布 installer、tag 或 release status；有任何產品 binary 變更都必須使用新版本。

開始前先核對外層 archive SHA-256 與 `BUNDLE-SHA256SUMS.txt`；manifest 覆蓋它自身以外的每一份 regular payload file，manifest 自身則由聊天外提供的 archive bytes／SHA-256 保護。再完整閱讀本文件、`v0.1.9-windows-external-candidate-identity.json`、凍結的 `windows-external-qualification-plan.zh-TW.md` 與 `product-spec.md`。完整計畫中的其他 lifecycle row 不在本 handoff 的授權範圍；若文件 identity 不一致，停止且不得執行 installer 或 fixture。

## 1. 唯讀 preflight

使用全新、可重設、拋棄式 Windows x86-64 OPERATOR snapshot。不可使用個人帳號、production target、客戶資料、provider credential 或無關專案。記錄 Windows edition／version／build、architecture、account privilege／UAC model、virtualization capability、snapshot ID 與 network profile，但不要記錄 account name 或 SID。

在 PowerShell 設定本次精確路徑，再以 `Get-Item` 與 `Get-FileHash -Algorithm SHA256` 核對 installer、managed-runtime manifest、公開 `SHA256SUMS.txt`、Node archive 與 fixture 的 bytes／digest。公開 checksums 中的 installer 與 managed-runtime manifest 行必須和本文件完全一致。解壓 Node archive 後，以相同方式核對 `node.exe`。不可使用 `Unblock-File`、`Set-ExecutionPolicy` 或降低系統 policy；若檔案被 policy 阻擋，就把 WL-13 留為 `not-observed` 並停止。

先確認 `private-diagnostic\wl-13` 已存在，而且其中沒有 `windows-localhost-fixture-receipt.json`。Fixture 會拒絕覆寫 receipt。不要為了重跑而刪除既有 receipt；還原 clean snapshot，使用新的空 handoff。

## 2. 啟動 fixture

在獨立 PowerShell 視窗以前述精確 `node.exe` 執行；所有路徑都必須是絕對路徑：

```powershell
& '<HANDOFF_ROOT>\portable-runtime\node-v24.15.0-win-x64\node.exe' '<HANDOFF_ROOT>\scripts\release\windows-localhost-fixture.mjs' --receipt '<HANDOFF_ROOT>\private-diagnostic\wl-13\windows-localhost-fixture-receipt.json'
```

只有看到下列形狀的單行 JSON，才表示 fixture 已持有 endpoint：

```json
{"event":"ready","address":"127.0.0.1","port":9001,"family":"IPv4"}
```

`EADDRINUSE`、runtime mismatch、沒有 `ready`、提前退出或任何其他錯誤一律 fail closed。不可按 Start，不可探測、停止或重新設定既有 port owner，也不可改 port。Fixture 不接受 host／port override。

## 3. 完成真正 installed-desktop journey

1. 從精確 v0.1.9 installer 完成正常 Windows 安裝。任何 UAC／secure-desktop 畫面都暫停 computer use，由真人親自處理；不得把 administrator credential 交給 Codex。
2. 開啟已安裝的 desktop，不可改用 development build 或 synthetic CLI case。
3. 建立或選取本次 disposable project，選擇 localhost quick task，畫面上的唯一 target 必須精確為 `127.0.0.1:9001`。
4. 若同一聊天中 owner 已明確授權 AUTO-OPERATOR 對此唯一 localhost target 按 combined Start，Desktop Codex 才可按一次並記錄 `localhostStartControl: agent-with-explicit-user-authorization`；否則由真人核對 scope 後親自按一次並記錄 `human`。不可加入第二次 consent，也不可擴大 target。
5. 等待 task 真正執行。Passing WL-13 必須由 installed app 回報 `reachable`，保存 canonical UUID report，關閉後重新開啟同一 project，並證明報告仍可用。
6. 從 desktop 執行 HTML export，記錄固定 filename、bytes 與 SHA-256。真人必須在暫停 model capture 後於本機打開 HTML，僅回傳 `readable`／`not readable` 的結果；不得把 HTML、Technical details、raw target evidence、畫面內容或 logs 放進模型。
7. 檢查產品顯示的 exact cleanup plan。只能使用產品支援的 cleanup，且只能處理 verified product-owned disposable state；ambiguous 或 unrelated state 保持不動。不要執行 all-data removal。

若沒有人能在 model capture 暫停時完成 HTML readability observation，已嘗試的 row 必須是 `inconclusive`，使用 `reasonCode: required-observation-unavailable`；不可因為 export 已產生就宣稱 passing。

## 4. 正常停止並保存 receipt

Desktop journey 結束後，回到 fixture 視窗按 `Ctrl+C`。不要用 Task Manager、`Stop-Process` 或強制關機終止它。正常停止會輸出 `stopped` event，並以 exclusive create 寫出：

```text
private-diagnostic/wl-13/windows-localhost-fixture-receipt.json
```

Receipt 只含固定 runtime／binding／health identity、timestamps 與 redacted counters。`tcpConnectionsAccepted` 必須顯示執行期間至少有一個真實 connection，才能支持 `fixture-observed-real-connection`；若 receipt 缺失、counter 不支持該觀察或停止不乾淨，保留已取得的結果並記為 `failed` 或 `inconclusive`，不可補造 counter。

## 5. 建立誠實 record

依 [Windows installed-lifecycle schema](windows-installed-lifecycle-evidence.schema.json) 與 WL-13 contract，把已記錄的結構化事實寫到唯一 canonical path。不要從本文件複製一份假 passing JSON，也不要把預期結果當成觀察結果。

只有以下五項都由本次執行支持時，checks 才能全部為 `passed`：

1. fixture 確實只監聽 Windows host `127.0.0.1:9001`；
2. installed app 確實回報 `reachable`；
3. clean-shutdown receipt 確實記錄真實 connection；
4. fixed harness identity 證明沒有 hidden host／port expansion；
5. 真正 installed-desktop report／reopen／readable HTML journey 完成。

產品行為不符就保存 `failed` 與相符 reason code；環境、人工 readability 或 evidence chain 不完整就保存 `inconclusive`。Validator 接受誠實的 `passed`、`failed` 或 `inconclusive` shape，但不會替 operator 判定事實，也不會把缺少的證據補成 passing。

`harness` 必須逐字保存上述 approved policy，包括 source commit、path、fixture digest、contract version，以及完整 Node distribution／executable identity。所有 timestamp 都必須是 canonical UTC，check timestamp 必須位於 execution start/end 之間，record `observedAt` 不得早於 execution end。

## 6. 執行 parameterless local validator

確認 `redacted-output` 只有唯一 canonical record，再用同一個精確 portable Node 執行，不能帶任何 argument：

```powershell
& '<HANDOFF_ROOT>\portable-runtime\node-v24.15.0-win-x64\node.exe' '<HANDOFF_ROOT>\scripts\release\validate-v019-wl13-observation.mjs'
```

Validator 會：

- 從自身固定位置解析 `HANDOFF_ROOT`，不接受 path、candidate 或 policy override；
- 逐層要求唯一 `redacted-output/windows-installed-lifecycle/wl-13/runtime_reconciliation.json`，拒絕 symlink、hard link、special file、額外目錄或額外檔案；
- 使用 lifecycle validator 綁定完整 v0.1.9 candidate、installer、runtime manifest 與 `WINDOWS_APPROVED_LIFECYCLE_HARNESS_POLICIES`；
- 成功時只輸出 lane、row、boundary、誠實 record outcome、固定相對路徑、bytes 與 SHA-256；
- 失敗時只輸出固定 error code，不回顯 JSON、detail、reason、Windows path 或底層錯誤。

驗證失敗不代表可以調整 claim 直到通過。只能回到原始 structured observations 修正實際的 transcription error；若事實本身不足，就保留 `failed`／`inconclusive`。回收時只交付 canonical JSON、validator 的安全 summary 與其 hash，不要交付 private diagnostics，也不要讓 Desktop Codex commit、upload 或 dispatch protected importer。
