# v0.1.3 one-click Windows setup pre-release

`v0.1.3` is the next installable public preview on the way to stable `v0.2.0`. It focuses on the
Windows first-run problem found during hands-on testing: the app no longer makes a newcomer open an
Administrator PowerShell window just to prepare WSL 2.

## What changed

- **Fix this for me / 交給程式處理** is now the primary action when WSL 2 is missing, disabled, or
  outdated.
- Windows shows its standard administrator confirmation once. After approval, the app waits for
  Windows, checks the result, and continues setup automatically.
- A required restart becomes the only next step. The app never restarts Windows automatically or
  begins the managed-runtime image download before Windows is ready.
- Manual Microsoft commands remain available under **Other ways / 其他方式** instead of leading the
  page.
- The same plain-language action and progress state appear in both the setup page and sidebar, in
  English and Traditional Chinese.

## Narrow administrator boundary

The repair command accepts no executable, parameters, or operation from the webview. The backend
derives one allowlisted action from the exact current failed prerequisite and runs only the
Windows-owned `System32\wsl.exe` with fixed `--install --no-distribution` or `--update` arguments.
It does not invoke PowerShell or `cmd.exe`, elevate a project helper, receive the administrator
password, install a Linux distribution, or restart the computer.

## Testing status

The preview retains the existing exact-scope security assessment workflow, local cases, evidence,
and provenance. GitHub publishes it only after the tagged cross-platform installer and fresh-host
qualification workflow passes. Fresh hosted qualification jobs on Ubuntu 24.04, macOS 15 Intel,
and Windows 2025 must each complete managed-runtime install, real machine start, the fixed
network-disabled Gitleaks container probe, stop, purge, and private-state cleanup.

It remains a pre-release for hands-on testing; the planned IAM-newcomer study and subsequent formal
QC/code review remain part of the stable `v0.2.0` process.
