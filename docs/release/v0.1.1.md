# v0.1.1 security and consistency repair

`v0.1.1` preserves the immutable `v0.1.0` release and replaces it as the recommended release line.
The engine images, rulesets, feeds, and immutable pins remain the reviewed `v0.1.0` set; the
built-in adapter contract advances to `v0.1.1`. This patch changes application behavior, storage,
runtime controls, validation, and tests without silently changing scanner artifacts.

## Security and integrity fixes

- Container pause, resume, and stop operations now require an immutable container ID plus exact
  ownership, deterministic-name, and pinned-image proof. Cancellation without that proof terminates
  only the scanner runtime process tree.
- Provider bootstrap records cleanup intent before mutation, binds provider-generated identifiers
  atomically, and fails closed when an identifier cannot be reconciled.
- Case changes use durable revisions and compare-and-swap updates. Live worker output, pause/resume,
  and finalization share one coordination boundary so stale writers cannot overwrite newer state.
- Adapter limits, malformed output, missing paths, and unsafe XML constructs produce incomplete
  results instead of a false-success assessment. Diffs and handoffs preserve completeness issues.
- Evidence bundles validate the exact historical finding snapshot, engine and run provenance, raw
  artifact hashes, and non-empty evidence references. Current canonical data cannot substitute for
  a different historical observation.
- Managed runtime repair handles corrupted, non-traversable, read-only, and reparse-point entries
  without following links outside the private runtime roots. Windows-specific repair tests run on a
  Windows CI host.
- The isolated bootstrap broker has bounded connection, callback, process termination, and reaping
  behavior, including fragmented callback input on Windows.
- Scope approval, false-positive expiry projection, OCSF export status, UI submission behavior, and
  event-subscription cleanup now share the canonical domain rules.

## v0.1.0 cleanup migration

Legacy filesystem cleanup obligations are imported into SQLite in an immediate transaction before
the exact legacy file is removed. Migration refuses live cases, symlinks, unexpected paths, and
conflicting records; retries are idempotent. Artifact deletion commits the durable cleanup
obligation first and retains recoverability if final filesystem cleanup cannot complete.

Because `v0.1.1` changes the adapter completeness contract, comparisons between a `v0.1.0`
baseline and a `v0.1.1` rerun are conservatively marked incomparable unless an explicit reviewed
adapter migration is added. The product does not guess that skipped legacy evidence was equivalent.

## Release trust

The release pipeline rebuilds Linux, universal macOS, and Windows installers from the exact tag,
verifies complete checksum and updater coverage, and publishes build-provenance attestations.
Apple Developer ID, Apple notarization, and Windows Authenticode are not configured; operating
systems may therefore display an unidentified-developer warning even though updater signatures,
checksums, and GitHub attestations verify the published bytes.
