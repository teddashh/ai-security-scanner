# v0.1.1 historical change summary

This record summarizes product and data-integrity changes made on the `v0.1.1` line. It is not current guidance; see the [product specification](../product-spec.md).

## Useful changes retained

- Runtime pause, resume, stop, and cleanup were bound to exact product-owned resources instead of names alone.
- Case writes gained durable revisions so stale workers could not overwrite newer state.
- Adapter errors, malformed output, unsafe XML, and exceeded limits became incomplete results rather than false success.
- Evidence bundles retained the exact historical finding, engine, run, and artifact hashes.
- Managed-runtime repair stopped following links outside private runtime roots.
- Scope, false-positive expiry, export status, UI submission, and event cleanup were aligned to shared domain rules.

## Historical data migration

Legacy cleanup obligations were imported into SQLite before the old file was removed. Migration refused live cases, links, unexpected paths, and conflicting records, and retries were idempotent.

Comparisons across the old and new adapter completeness contracts remained conservative unless an explicit migration made them comparable. The product did not guess that skipped evidence was equivalent.
