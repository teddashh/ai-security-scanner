# v0.5.0 consolidated desktop package

[繁體中文](v0.5.0.zh-TW.md) · [Release records](README.md)

Status: Windows, macOS and Linux installer packages are built and verified as a commit-bound validation set. The published stable release remains [v0.4.1](v0.4.1.md); v0.5.0 has not been publicly released.

This package collects all 32 commits after the v0.4.1 source (`94ef7be18e83630553d9a72746b0533695df1ee2`) through `c5a0a6693a1ad9997ee16b9a3d690d38a44b7406`. One commit records the previous delivery; the other 31 contain product, report and documentation updates. The [complete inventory](v0.5.0-changes.json) records every commit.

## Desktop and reports

- **One problem card for one problem.** Group the same vulnerable package, exposed secret, or same-line code findings with the same CWE. Retain original findings, upstream identifiers, evidence, severity and remediation. Show original-finding counts and the representative chosen by the report.
- **Check fixes by problem card.** Track fixed, partly fixed, remaining and new problems. Preserve a card's representative when its line moves; show how many original findings remain when partly fixed. The app and HTML comparison use the same order as Results.
- **Use the latest local folder.** Reselect a folder before checking fixes and scan a fresh read-only snapshot within its approved scope. Saved evidence remains available for comparison. My scans counts problems from the latest finished scan.
- **More useful next steps.** Cloud configuration, identity and cloud-resource findings have fitting labels and actions. Grouped next steps explain whether one fix applies, where to make it and how to check it. Upstream severity, benchmark classification and product priority remain distinct.
- **Clear progress and scanner details.** Distinguish partial completion from failure. Show scanner versions and update dates, including source-built version and commit details. Inventory tools no longer request irrelevant vulnerability-data updates.

## Guides and examples

The 25 upstream integrations and published image digests are retained. Original HTML report attachments and access-cleanup helpers already delivered in v0.4.1 are included.

The Linux runtime builder also pins the available Alpine `zlib-dev` and `zlib-static` revision `1.3.2-r1`, and `libseccomp-static` version `2.6.1-r0`; the previous packages were removed from the package index. Runtime binaries are rebuilt and verified by the package workflow.

Security updates pin runtime dependency rustls to `0.23.45` ([TLS advisory](https://github.com/advisories/GHSA-2mjx-qc3c-rqvc)) and development dependency source-map-js to `1.2.2` ([source-map advisory](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)). These targeted updates are included in package preparation alongside the collected product changes.
