# v0.1.4 historical change summary

This record summarizes guided-scan changes made on the `v0.1.4` line. It is not current guidance; see the [product specification](../product-spec.md).

## Useful changes retained

- Users chose what to scan—network, website, IP, source, infrastructure code, cloud, container, or Kubernetes—before seeing relevant inputs.
- A private-subnet suggestion required one visible user confirmation and did not silently probe or choose a target.
- One review step showed the selected target and activity.
- Multiple cloud accounts were not treated as interchangeable; quick confirmation remained tied to the exact account that discovered the asset.
- Failures could produce a redacted diagnostic without targets, local paths, raw evidence, credentials, or scanner text.
- Progress labels described what the number actually measured.

The old whole-plan readiness decision is superseded. Current behavior saves the requested run and known tasks before task-local preparation, keeps successful sibling checks usable, and records unavailable work as an explicit coverage gap.
