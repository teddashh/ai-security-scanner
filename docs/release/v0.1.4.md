# v0.1.4 actionable scan-flow pre-release

> **Historical / non-normative release-line record.** This file preserves claims and plans written for this version line. It does not define current product behavior, release gates, recovery, consent, or installation advice, and it is not evidence that every described path shipped or passed. The [canonical product specification](../product-spec.md) controls; current implementation gaps are tracked in the [product audit](../product-audit.md).

`v0.1.4` is the installable public preview that fixes the failed 0/0 home-network experience found
during hands-on testing. It replaces a scanner-first setup maze with one guided path for each thing
you want to check.

## What feels different

- Choose a home or office network, website, external IP, source code, infrastructure as code, cloud
  account, container image, or Kubernetes configuration. The app shows only the setup that use case
  needs.
- The installed app can suggest one safe private subnet from local network settings. It does not
  probe the network or silently choose a target; you accept the suggestion with one visible click.
- Home-network and external-IP checks start with a useful, bounded common-service preset. Website
  checks keep the exact protocol and port you entered. Advanced options are still available.
- One clear confirmation covers the selected target and scan activity. The app no longer spreads
  that decision across unrelated or hidden controls.
- When a case has more than one account from the same cloud provider, the quick confirmation is
  available only for the exact account that discovered the selected target. The app never treats two
  AWS, Azure, Google Cloud, or Microsoft 365 sign-ins as interchangeable.
- `v0.1.4` did not create a run when no scanner passed its readiness checks. That behavior is
  superseded and must not be copied: Start now persists the requested run and known tasks first,
  then records per-task failures or `not_tested` coverage in the same partial/no-checks master
  report while independent work continues.
- This preview also checked disposable helpers and resume inputs before saving new run state. The
  current contract preserves the prior result but commits the new requested work before runtime,
  gateway, image, credential, or engine preflight; an unavailable dependency affects only its task.
- Setup and run failures can produce a downloadable redacted diagnostic with technical statuses,
  error codes, versions, and counts, but no target names, local paths, raw evidence, or scanner text.
- Scan progress names the number it actually measures: targets that finished every applicable
  check, rather than incorrectly calling that number a count of scanner checks.

## Superseded shared readiness behavior

`v0.1.4` used a whole-plan, pre-persist readiness decision for local tools, provider capacity,
credentials, and engine compatibility. The current orchestrator must not reuse that model. The
combined Start action atomically records the exact assertion, requested coverage, run, and known
target-stage-engine tasks. Task-local preflight follows. Missing runtime, gateway, credential,
engine, or worker capacity becomes an explicit outcome for the affected task, while successful
siblings and already saved evidence remain available. Immediate integrity checks still occur before
an exact artifact or credential is used, but they do not erase the run or become global readiness.

Local source-code, IaC, container, and Kubernetes routes now use real immutable snapshots created by
the backend; questionnaire text is never presented as a scan target. Cloud setup starts with the one
provider selected for the case. Website, external-IP, and internal-network routes keep distinct
target and protocol behavior while sharing the same readiness contract.

## Windows setup

The one-click WSL 2 screen introduced in `v0.1.3` was still part of this historical build. It is
superseded by signed-installer detection/preparation plus automatic resume into the main shell.
Manual Microsoft commands are not a fallback in the current beginner journey.

## Historical testing status

The `v0.1.4` Linux and Windows fresh-host qualification required the product and managed runtime to
be installed and started, the fixed isolated Gitleaks container probe to run, and the test state to
be stopped, uninstalled, and checked for cleanup.

The macOS 15 Intel job was required to verify the DMG, app layout, all companion executables,
packaged runtime manifest, CLI, desktop startup, and cleanup. GitHub-hosted macOS did not provide the nested
virtualization required by the AppleHV managed machine. The network-disabled Gitleaks container probe
and every runtime operation were therefore recorded as `not_observed`, not passed.

That historical channel accepted this limited evidence only for a pre-release and planned to
require a real managed-runtime lifecycle on a suitable Mac for its stable release. Current
publication instead withholds only the exact unqualified artifact or unsupported capability and
does not make an unrelated platform wait for it.

This was a public testing pre-release on the way to `v0.2.0`. Its deferred formal QC/code-review
sequence is historical and does not replace the current human-path-first acceptance order.
