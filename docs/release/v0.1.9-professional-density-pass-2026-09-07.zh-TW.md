## 結論

本輪把主要桌面流程從「每一層都解釋很多」改為「第一層只保留當下決策、狀態與風險」。新手引導沒有移除，而是改成短標題、明確狀態、單一主要動作與可展開的細節；維運、框架、格式與技術內容退到 progressive disclosure。

Start、Cases、Coverage、Findings、Progress、Export、Settings 七個主要頁面都已在 432 px 寬的實際 browser dev surface 逐頁檢查。這證明本輪 source 的 rendered hierarchy、窄版密度與主要互動，不是 Windows installed candidate 的真實掃描證據。

已發布的 `v0.1.9` installer、tag 與 release assets 都沒有被修改。本輪是 `v0.1.9` 之後的 source checkpoint；要變成新的可安裝交付物，仍需建立新的 immutable version／candidate。

## 介面實際改動

### Start

- 首層改成 `Security checks`／`資安檢查`，只顯示四個主要掃描類型。
- 次要類型集中於 `More scan types`；適用範圍與限制只保留一份可展開說明。
- 縮小 hero、卡片、按鈕與頁面間距；窄版仍維持可掃讀的兩欄選擇。

### Cases

- 專案列表標題只保留任務名稱。
- Current project 首層最多顯示三個平台標籤，其餘用數量彙總。
- 驗證資料、輔助說明與次要 metric 收進細節；hero 高度明顯降低。

### Coverage

- 已有輸入時預設收起 source setup；沒有輸入時保持開啟。
- 項目與授權狀態改成短標籤及緊湊列表；超過四個項目不再鋪滿大型卡片。
- `scannedAssets` 改為誠實的 `Items fully checked`／`已完整檢查的項目`，不再錯叫成 checks。
- 技術細節收起，但 exact target、限制、未授權狀態與待清理雲端權限仍不得被隱藏。

### Progress

- 首層只保留狀態、整體進度、時間與需要注意的數量。
- 移除四張重複大型 metric 卡；activity 保持簡短，技術細節收起。
- Runtime 的目前 stage、精確 bytes／progress 仍在首層，避免精簡後失去可判讀性。

### Findings

- 首層先回答：要求了什麼、實際測了什麼、限制、時間與排除項。
- 缺少資料就明示 unavailable，不用推測或用空值假裝完整。
- Priority findings 放在 metrics 之前；framework／expert filters 收起。
- 預設不自動打開第一筆 finding；使用者選取後才顯示細節。
- 沒有保存 tested dimensions 的已完成／部分完成 check 仍會列出，並明示精確範圍未保存。
- 窄版 priority row 只保留 severity、標題與 asset，避免同屏資訊淹沒主要判斷。

### Export

- 預設只顯示 HTML／JSON；其他格式集中於 `More formats`。
- 首層用一行合併 privacy、selected scope 與 integrity／signing 限制。
- 未簽章 SHA-256 明確說明只能偵測變更，不能證明作者、完整性或正確性。

### Settings

- 首層只保留 language、storage/privacy 與 local tools。
- 清楚說明資料預設留在本機，但連接來源或主動 export 時可能離開裝置。
- 工具 unavailable／unchecked 的動作改名為 `Choose a scan`／`選擇掃描`，不再假裝按鈕會直接修好 runtime。

### App shell 與跨頁狀態

- 導覽名稱縮短，頁面留白與 notice 密度降低。
- 同時發生 case recovery、stale data、selection failure 時只顯示一個 banner，但其中會列出全部真實狀態與各自可用的 retry。
- Provider panel 以 case identity remount，避免上一個專案的連線 state 洩漏到下一個專案。
- 一般 provider access 明示唯讀；temporary bootstrap 明示可能在另一次確認後建立受限 IAM resources，不再用錯誤的「完全不改雲端資源」包住兩條不同路徑。

## 實際 rendered UI 走查

使用最新 source 的 browser dev surface，逐頁檢查 432 px 窄版：

1. Start：四個主要 target card、收合的 More scan types／Scope & limits，以及單一 runtime preview。
2. Cases：緊湊 current-project hero、三個主要平台標籤、兩個小 metric 與可展開揭露。
3. Coverage：收合的 source setup、簡短狀態 chip、誠實 warning、緊湊 asset rows 與精簡確認區。
4. Findings：incomplete warning、三筆 priority row、四個小 metric、收合 filters/how-to，且沒有自動打開 finding detail。
5. Progress：單一 overview、activity、attention chips 與 checks list。
6. Export：HTML／JSON first、收合 More formats、單一 integrity/privacy decision line。
7. Settings：language、storage/privacy、local tools 三個區塊。

本輪沒有執行 target scan，也沒有把 browser preview 冒充 Windows native E2E。

## 安全與誠實性審查攔截

精簡不是把重要真相藏起來。最後的 P0/P1 審查實際找到並修正：

1. 切換 case 時 provider authorization state 可能沿用：改為依 `caseId` remount。
2. 單一 recovery banner 可能壓掉同時存在的 stale／selection failure：改為一個容器呈現全部真實狀態與正確 retry。
3. Runtime stage 與精確 bytes 被收到細節：恢復到首層的緊湊 progress。
4. 一般 provider 與 IAM bootstrap 共用「不會改資源」文案：拆成符合實際能力的兩種說明。
5. asset 數量被標成 check 數量：改為 `Items fully checked`。
6. 沒有 dimension payload 的已測 check 被首層漏掉：仍列出 check，並揭露精確範圍未保存。
7. Settings action 只是導向 Start 卻宣稱會 retry／prepare tools：改成 `Choose a scan`。
8. 已有來源的 reopened cloud case 可能把未完成 bootstrap cleanup 藏在收合區：保留可見提示與清理入口。
9. `Actually tested · Time` 不再用可能包含 failed／cancelled sibling 的全 run 時窗冒充 tested-only 時窗。
10. Generic engine 的完成座標可能在首層露出 engine ID／內部 asset ID：改用已解析的 check 與 target 名稱；原始座標只留在收合技術細節。
11. 沒有任何 provider source 時，既有 cleanup record／lookup error 可能進入死路：零來源狀態仍保留記錄、retry 與加入對應來源的明確下一步。
12. 非同步出現的 cleanup warning 可能不被輔助科技讀到：改為 alert，Review 後聚焦單一、有標籤的 cleanup region。

沒有發現需要以更多說明、更多 gate 或更多 qualification ceremony 解決的問題。
