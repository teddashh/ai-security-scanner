## 更新內容

- Prowler 標題說明實際失敗原因；相關 AWS 發現合併成同一個修正動作，保留原始識別碼、證據、嚴重度與修正建議。
- 唯讀連線過期後直接提供重新連接再掃描；受阻的繼續操作與 Markdown 顯示已修正。
- Semgrep `1.174.0-4` 使用固定的 1,493 條舊版上游規則加上四條產品規則。詳見[發布證據](../engines/semgrep-publication-2026-10-03.md)。
- kube-bench WARN 與 KICS 檔案／query 失敗會標示涵蓋範圍未完成，其他已完成發現仍保留。
- Microsoft 365 已更新四項核准的 PIM 讀取權限與固定的 ScubaGear／Maester 映像檔；仍待擁有者登入後重新實測。
- [映像檔維護筆記](../engines/image-build-index.md)涵蓋全部 25 個引擎紀錄及 gateway。

候選來源：`6b61e9ef72f90174ef7310f80e766aba61c9428d`。Gateway 沿用 `0.3.0-1` 的固定 digest；runtime 與 qualification 分別核對桌面版本及精確映像檔來源，不因桌面 patch 版本變動而重建 gateway。

## 候選程式額外實測

本機以精確 Debian 候選包解開後的安裝布局及獨立資料目錄實測，補充前述新 runner 的套件安裝驗證；這不是第二次系統安裝，也不是新手真人研究。實際桌面程式啟動自己的 managed runtime，對受控的三檔案本機快照執行 Gitleaks 與 Semgrep。兩項檢查均以 exit code 0 完成：Semgrep 回報四筆發現，Gitleaks 零筆。六份原始產物、上游規則識別碼、嚴重度與證據均保留。

中英文 Results 均正常呈現，兩份遮蔽版 HTML 都從桌面程式保存。重新開啟後，四筆發現的識別碼與 fingerprint 不變，兩份匯出均不含測試用假 token。390、768、1440px 瀏覽器檢查沒有 script error；768px 報告仍有橫向捲動，390 與 1440px 則符合視窗寬度。平板寬度的匯出布局仍列為後續改善。
