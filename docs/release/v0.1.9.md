# v0.1.9 public testing prerelease

> **Historical / non-normative release-line record.** This page records what the v0.1.9 testing
> prerelease claims. It does not define current product behavior, release gates, recovery, consent,
> or installation advice. The [canonical product specification](../product-spec.md) controls those
> rules.

`v0.1.9` is a public testing prerelease, not a stable deployment or a beginner-ready installer
recommendation. The release workflow may offer each installer only after that exact artifact passes
its automated platform qualification. Its release metadata and generated notes independently state
whether the beginner path, installed Windows lifecycle, operating-system signing, notarization, and
updater were actually observed for that artifact.

The Windows installers are intentionally published so an independent operator and beginner can test
the final downloadable bytes with the
[Windows external qualification plan](windows-external-qualification-plan.md). Until those external
records exist, the release must say that the paths are unobserved. Windows Authenticode is not
configured, so Windows may show an Unknown publisher or reputation warning. That does not prevent an
otherwise qualified installer from being offered in this testing channel, but it does prevent this
artifact from being represented as signed, recommended, beginner-ready, or stable.

## What changed since v0.1.8

- Verified product-owned managed-runtime material can recover from its digest-anchored packaged
  cache. Ambiguous or unrelated runtime state remains untouched, and an affected runtime or engine
  failure remains scoped to its dependent tasks.
- Reports and result screens distinguish completed, partial, failed, disputed, unattributed, and
  not-tested work more precisely. A failed run is not called complete, and unavailable export formats
  or public-record checks are not presented as if they ran.
- Finding summaries, impacts, priorities, next steps, warnings, tested dimensions, limitations,
  control-mapping reasons, and verification explanations retain their source facts and are readable
  in English and Traditional Chinese.
- Related observations from different engines are grouped reversibly without erasing their separate
  evidence. Redacted exports withhold cloud identifiers that could not be attributed to a known
  source.
- The desktop layout, focus treatment, readable type sizing, reduced-motion behavior, and compact
  navigation have been improved across supported window sizes.
- Microsoft 365 adapter and managed-image revisions preserve partial and disputed outcomes instead
  of silently treating missing controls or unreadable wrapper output as a clean result. These engines
  remain separately admitted artifacts; they are not bundled into the desktop installer.

## What the release does not claim

- Automated, modeled, source-level, or contributor testing is not a qualifying independent-beginner
  observation.
- One Windows installer format does not qualify another, and a Windows result does not qualify Linux
  or macOS.
- A SHA-256 checksum, GitHub build attestation, or Tauri updater signature is not Windows
  Authenticode and does not prove publisher identity.
- A partial report, zero findings, or an unavailable scanner does not mean that unexecuted coverage
  passed.
- Evidence collected after publication remains bound to the exact downloaded filename, byte length,
  SHA-256, source commit, and installer type. It cannot be copied to rebuilt bytes or to `v0.2.0`.

If testing finds a candidate defect, the immutable `v0.1.9` tag and installer bytes are not replaced.
The fix belongs in a new version and requires fresh artifact qualification.
