## Open specification gaps

1. **A19 same-version packaged-component repair remains open.** The running app
   has no independent authenticated same-version installer or payload cache.
   Repairing a corrupt packaged component from the same corrupt resource tree
   would be circular. The current safe behavior is task-scoped degradation and
   an honest recovery path. Automatic repair needs an independently signed or
   digest-anchored source, out-of-process exit/repair/relaunch coordination, and
   installed-Windows qualification for missing, corrupt, locked, and
   interrupted cases.
2. The signed case bundle still contains case-wide records alongside the
   selected-run readable report. Do not claim that every bundle member is
   selected-run-only until the acceptance condition is proven end to end.
3. Administrators-owned, conditional/object-ACE, or foreign-inheritable-write
   legacy product roots deliberately fail closed. Enterprise policy
   compatibility needs real qualification before broadening admission.
4. No human evidence currently proves the ten-minute beginner first-value
   target or complete UI accessibility/mobile behavior.

## Recommended next work

1. Perform an installed Windows human path using the exact unsigned candidate
   only in an explicitly non-production test environment, recording the exact
   installer SHA-256 and every observed outcome.
2. Design A19 around an independently authenticated same-version repair source;
   do not weaken manifest or DACL verification to simulate repair.
3. Decide whether the signed case bundle should become strictly run-scoped or
   explicitly remain a case-wide bundle containing run-scoped reports.
4. Split the frontend bundle only after measuring startup impact; do not turn
   the current warning into an unrelated release gate.
