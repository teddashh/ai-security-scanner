# v0.1.5 Windows launch and visible scan-activity pre-release

`v0.1.5` is the Windows-first public preview that removes the repeated Ready/Repair experience and
makes scan activity visible. Open the app, let it prepare the scan tools once, and see what is
happening before and during every scan.

## What feels different

- On first launch, the app checks what Windows prerequisites are already installed and prepares the
  private local scan tools automatically.
- If Windows itself needs a change, the app uses the normal Windows approval dialog. A required
  restart stays visible and under the user's control.
- A temporary scan-tool connection problem can be retried. A missing or invalid packaged component
  no longer sends the user through the same Ready/Repair loop; the app explains the problem and
  links to the latest installer while preserving existing cases.
- Before a scan starts, the activity view shows when readiness was checked and why the scan is
  waiting. During a scan, it shows the active scanner, what comes next, the current wait reason, and
  the last saved progress.
- If updates take longer than expected, the app says so without pretending that a deliberately
  paused scan is stuck.

## One event log across every scan route

Website, external-IP, internal-network, source-code, infrastructure-as-code, cloud, container, and
Kubernetes checks now use the same activity model. The user sees one timestamped sequence instead
of having to infer progress from a spinner or open unrelated setup screens.

When a scan cannot start, the event log names the useful next action. Technical details keep a
stable blocker code for support and troubleshooting. A downloadable redacted diagnostic is also
available before a run exists and while a run is in progress. It includes safe timestamps,
statuses, phases, versions, and counts, but excludes target names, local paths, raw evidence,
credentials, and raw scanner output.

## Startup and control

First-launch preparation does not start a security scan. The app still waits for an explicit Start
action before contacting an approved target, and it does not add targets or widen the selected
scope. Existing local cases, evidence snapshots, cleanup obligations, and historical provenance
remain intact across the update.

## Testing status

This is a public testing pre-release on the way to `v0.2.0`. The release pipeline still builds and
qualifies the native installers and their packaged components. The macOS 15 Intel job verifies the
installed app, its companion executables, and its packaged runtime manifest. Because the hosted Mac
cannot run the required nested virtualization, the network-disabled Gitleaks container probe and
every runtime operation are recorded as `not_observed`, not passed.

This limited evidence is accepted only for a pre-release; a stable release still requires a real
managed-runtime lifecycle on a suitable Mac.

Formal QC and code review remain scheduled after the full product workflow has been exercised end
to end, as planned.
