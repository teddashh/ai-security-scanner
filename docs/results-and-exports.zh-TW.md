# 結果與匯出

[English](results-and-exports.md) · [文件](README.zh-TW.md)

結果只會開啟終態掃描；進行中的掃描維持在進度頁面。

## 先看第一層

資產摘要會讓每個選定資產取得一個狀態：

| 狀態 | 意義 |
| --- | --- |
| 發現問題 | 至少一個安全問題影響這個資產。 |
| 已完成檢查未發現問題 | 明列範圍內的安全檢查已完成，且沒有 finding。 |
| 未完成或失敗 | 要求的安全工作沒有完成；其他已完成結果仍保留在報告中。 |
| 尚未測試 | 這個資產沒有適用的安全檢查完成。 |

觀察到的服務會分開列出，不會計入弱點。

## 依優先順序處理

每個優先項目包含：

- 嚴重度與信心程度；
- 受影響資產與位置；
- 白話影響；
- 一個可直接執行的下一步；
- 適用時的回復與驗證方式；
- 技術細節中的上游掃描器、規則識別碼、證據與 remediation。

上游掃描器沒有提供評等時，嚴重度保持為 **Unknown**。

## 確認涵蓋範圍

涵蓋紀錄會列出選定內容、已完成檢查、實際涵蓋的目標維度，以及未執行的工作。同一個終態掃描可以同時包含有用 finding 與未完成涵蓋範圍。

連線觀察與盤點不會產生安全檢查完成狀態；後續掃描可以使用這些資料選擇適用的弱點或服務檢查。

## 重新開啟與比較

案件會保留目標、掃描輪次、finding、涵蓋範圍、證據參照與匯出歷史。重新開啟終態掃描時，會依保存事實重建同一份報告。複驗會把相容的後續掃描與已完成基準比較，並將 finding 標示為新增、持續、已解決或無法比較。

## 匯出

**好讀的 HTML** 是主要分享格式，內容順序與畫面一致，報告條款與技術紀錄位於最後。

結構化格式提供專業流程使用：

- JSON 保留產品報告模型；
- OCSF 保留正規化安全 finding；
- OSCAL 與 framework report 只帶入已審查且存在的控制項映射；
- case bundle 依匯出選項保存選定案件資料與參照證據。

所有匯出都來自同一個終態報告模型；SHA-256 紀錄會識別精確保存檔案。
