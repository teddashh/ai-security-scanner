# MCP Armor

Runs MCP Armor's two static configuration checks, `hardcoded_secrets` and `excessive_tool_permissions`, on one selected MCP configuration file inside a repository snapshot (`repository` asset, input profile `repository_working_tree`). A downstream `--config-only` mode keeps the run from starting or contacting any MCP server and from loading a model.

## How it is wired

- **Input.** On repository attach, `discover_mcp_configurations` lists files of at most 10 MiB accepted by `is_mcp_configuration_relative_path` (`mcp.json`, `mcp_servers.json`, `mcp*` or `*.mcp` names ending `.json`, `.yaml` or `.yml`, and a few editor settings files). More than 64 candidates clears the list and marks discovery incomplete. `annotate_repository_asset` auto-selects only a complete discovery with exactly one candidate; otherwise the user picks one (`select_mcp_configuration` command). The choice becomes two asset identifiers, `ai-security-scanner:mcp-configuration-relative-path` and `ai-security-scanner:mcp-configuration-sha256`, which reach the launcher in the scope document.
- **Planning.** The IT-environment path adds MCP Armor to a repository only when a configuration is selected (`localEngineIdsForAsset` in `src/pages/CoveragePage.tsx`). The backend default plan (`default_plan_includes_manifest` in `src-tauri/src/case_service.rs`) also keeps it as not executed when the user can still act: `mcp_configuration_discovery_incomplete` (decided first, so it is never reported as absence) or `mcp_configuration_unselected`. An absent configuration is left out of the default plan, and `mcp_configuration_absent` is a settled skip that does not make a run partial. The catalog `default_enabled` (false) is not read by the planner.
- **Network and resources.** Engine networking disabled. Catalog `execution.resources`: 512 MB memory, 1024 MB disk, 1000 CPU millis, 128 pids, 900 s. Read-only root filesystem and `/workspace`, all capabilities dropped (`src-tauri/src/container_runtime.rs`).
- **Invocation.** The launcher accepts only `--engine mcp-armor --workspace /workspace --output /output` and refuses a writable workspace. It reads `/run/ai-security-scanner/scope.json` (at most 1 MiB, unknown fields and trailing JSON rejected): schema `1`, engine `mcp-armor`, one `repository` asset with exactly one `local_artifact_read` grant that has an id, `confirmed_by` and `confirmed_at`, and exactly one workspace digest, configuration path and configuration digest. The path must be relative, clean, POSIX, at most 4096 bytes and end in `.json`, `.yaml` or `.yml`; no component may be a symlink; the file must be at most 10 MiB and match the digest. Then, with a fixed environment and a 10 min timeout: `python3 -m mcp_armor.cli scan --config-only --config <path> --report-type json --output /output/mcp-armor.json`.
- **Output.** `/output/mcp-armor.json`, a schema `1` envelope with `scanner_version`, `mode` `configuration_only`, `input_count`, `evaluated_input_count`, `complete`, `warnings`, `checks` and `findings`. `validateTerminalEvidence` requires one JSON value of at most 32 MiB, scanner `1.0.2`, one input evaluated, and non-null `complete`, `warnings`, `checks` and `findings`; the file is then set to 0600. Diagnostics are capped at 1 MiB.
- **Mapping.** `extract_mcp_armor` returns nothing, with a warning, unless schema, scanner version and mode match exactly.
  - A finding is kept only with check id `hardcoded_secrets` (type "Hardcoded Secret", severity `high`) or `excessive_tool_permissions` (type "Excessive Tool Permissions", `critical`, or `low` exactly when `disabled` is true), `entity_type` `configuration`, a `config_file`, and null `description`, `recommendation`, `affected_tool`, `affected_resource` and `affected_resource_uri`.
  - Secrets need `secret_type`, a positive `line_number` and a `matched_text_redacted` marker, whose text is never copied. Permissions need a server name plus `risky_tools`, `risky_permissions`, `risky_command_flags`, `risky_command` and `disabled`.
  - Rule id is the check id and severity is upstream's. Location is `<config_file> (<server, line or permission details>)`, family `McpSecret` or `McpConfiguration`, confidence basis `DeterministicPolicyEvaluation`.
- **Failed, partial, not tested.** A launcher refusal (scope, path, symlink, digest), the timeout or a non-zero upstream exit makes the container exit 126, and `src-tauri/src/orchestrator.rs` fails the run. Upstream exits 1 when the selected file cannot be read or parsed at all, so an unreadable configuration is a failed run, not a partial one. The run is partial, keeping findings from completed checks, when upstream reports a warning (`config_invalid`, `server_config_invalid`, `check_failed`), a check is not `completed`, a finding is malformed or carries detail text, a check's `finding_count` disagrees with its findings, or `complete` disagrees with the ledger.

## Downstream changes

- **Config-only patch** (`ae7732b5…`, 14 files), applied with `git apply` after a hash check, followed by a check that `__version__` is still `1.0.2`. It adds `scan --config-only`, which requires `--config`, refuses `--baseline` and non-JSON output, and exits 1 when no input was evaluated. It also adds `config_scan.py` (the envelope, structured warnings and the two-check ledger run with `fail_on_error=True`), defers the live connector import, moves the model dependencies behind a `prompt-injection` extra, and turns file logging off in config-only mode. Detector patterns, severities and decisions are unchanged (`docs/research/mcp-armor-evaluation.md`).
- The patch has not been submitted upstream. Plan `build_recipe.patch_audit` records 14 verified source-file transitions, pinned source references, the contribution rationale, owners and dedicated configuration-only fixtures. Remove when a native documented mode preserves both check outcomes/completeness without live connectors or model imports. Reviewed 2026-10-03; recheck on the next source update or by 2026-11-01.
- **Packaging.** `requirements.lock` holds five hash-pinned wheels (`--require-hashes --only-binary=:all:`); FastMCP, TheFuzz, Transformers and Torch are excluded, and the build fails if any of them is present. The upstream `src/mcp_armor` package is copied into site-packages rather than pip-installed. An in-build smoke runs `--config-only` on the patch's `tests/fixtures/config-clean.json`.

## Lessons from real runs

- 2026-09-19: the engine was listed but never ran (`runtime_image_unavailable`) -> the image published on 2026-09-14 by run 34810830035 had never been pinned, so the catalog said `image: null` -> re-verified anonymously and pinned (bdee717).
- 2026-09-19: on a project without MCP configuration the planner said no ownership-confirmed asset had the required permissions -> the reason-code boundary folded a missing selection into the permission case -> three reason codes, incomplete discovery decided first (cc43891); the skip is recorded on the repository it inspected (ffe6e01, 2026-09-21).
- 2026-09-25: repeat scans planned 10 checks instead of 8, including MCP Armor on a project with no MCP configuration, and the run read "Completed with gaps" -> the default selection kept an engine whose only barrier was an absent configuration (3e85d54) -> absent configuration left out of the default plan (fbcbdd0), and settled skips no longer make a run partial (efb1314).

## Updating this engine

Follow [section 4](../engine-maintenance.md#4-updating-an-engine), then:

- **Patch first.** On a new upstream release, check whether upstream now offers an equivalent configuration-only mode with structured completeness before rebasing the patch. A rebased patch needs its tests (`tests/config_only_test.py` in the patch), regenerated research fixtures, and the new hash in the Dockerfile check line and `io.ai-security-scanner.patch-sha256` label, plan `build_recipe.source_patch`, `sourcePatch` and `immutableDockerfileInputs` in `scripts/validate-engine-catalog.mjs`, `MCP_ARMOR_RESEARCH_PATCH_SHA256` in `tests/ci/product-document-contract.test.mjs`, `docs/research/mcp-armor-evaluation.md` and `docs/research/fixtures/mcp-armor/README.md`.
- **Source and lock.** Change the archive URL and checksum (Dockerfile, plan `build_recipe.source_archive`, validator `sourceArchiveSha256`, label), the `__version__` grep, `ruleVersion`, catalog revisions, and `requirements.lock` with its hash in the Dockerfile, label, plan and validator. The version `1.0.2` is also hard-coded in `validateTerminalEvidence`, `extract_mcp_armor`, the in-build smoke, the workflow import check and smoke, and the patch file name.
- **Output shape.** Re-check the envelope fields, the warning codes, the check ids and statuses, and every finding field the adapter requires. If upstream starts filling `description` or `recommendation`, every finding is dropped as partial until the adapter allowlists that field.
- **Tests.** Research fixtures `docs/research/fixtures/mcp-armor/` (`config-findings.json` is the adapter fixture; `config-clean.json`, `config-disabled.json`, `config-partial.json`), hash-pinned in `MCP_ARMOR_RESEARCH_FIXTURES`. Adapter tests from `mcp_armor_preserves_both_static_configuration_findings_without_secret_material` to `mcp_armor_exact_check_ids_map_without_using_configuration_controlled_text` in `src-tauri/tests/adapter_fixtures.rs`, which also pins the tag and digest in its registry test. Launcher tests `TestScopeBindsOneExactConfiguration`, `TestSelectedConfigurationMustMatchDigestAndContainNoSymlink`, `TestTerminalEvidenceReconcilesOneInput`; `tests/ci/mcp-armor-runtime-contract.test.mjs`.
- **Mapping.** `mappings/control-mappings.json` maps `hardcoded_secrets` and `excessive_tool_permissions` exactly. A content change needs a `mapping_version` bump.
- **Hard-coded tag.** `1.0.2-config-only.1` is in `engines/catalog.json`, `plan.json`, the Dockerfile label, the workflow `IMAGE_TAG` and concurrency group, `scripts/validate-engine-catalog.mjs`, `scripts/release/verify-publication-artifact.mjs`, `src-tauri/tests/adapter_fixtures.rs`, `tests/ci/mcp-armor-runtime-contract.test.mjs`, `THIRD_PARTY.md` and `docs/research/mcp-armor-evaluation.md`. Check with `grep -rn "1.0.2-config-only.1" --exclude-dir=node_modules --exclude-dir=target --exclude-dir=.git --exclude-dir=.upstreams`. `support_until` is 2026-12-12.
- **Publishing.** `launcher/go.mod` has no digest in the plan (`uncovered_baseline` in `engines/image-input-hash-policy.json`), and the root `.dockerignore`, although hashed, is outside the workflow's push paths; a change to either needs a manual tag bump and run. Do not skip the pin commit ([Shipping an engine image change](README.md#shipping-an-engine-image-change)); bdee717 shows the cost. The workflow smoke runs the launcher on `testdata/` and checks the envelope with `jq` (one critical `excessive_tool_permissions` finding, complete, no warnings); it does not run the Rust adapter.
- **Compare with raw output.** In the raw `mcp-armor.json`, each `findings[]` entry should be one finding with the same `check_id`, `severity`, `config_file` and server; `checks[].finding_count` should sum to the finding count. A partial run names the upstream warning code in its coverage warning.
