# Local launcher

`ai-security-scanner-engine-entrypoint` is the entrypoint of six local images: [Semgrep](semgrep.md), [TruffleHog](trufflehog.md), [Trivy](trivy.md) and [Grype](grype.md) for repositories, IaC projects and container images, and Kubescape and kube-bench for Kubernetes inputs. It is project-owned Go with no detection logic. It checks the mounts and the input profile, verifies the image's offline rules or databases, runs one fixed upstream command per pass, and validates the evidence file. [Gitleaks](gitleaks.md) has its own launcher; [Checkov](checkov.md), [Syft](syft.md) and [KICS](kics.md) run their upstream entrypoint with the catalog `command`.

| Item | Value |
| --- | --- |
| Source | `engines/images/local-launcher/main.go`, `main_test.go`, `go.mod` (Go 1.25.0, standard library only) |
| Fixtures | `testdata/oci-layout/`: a one-layer OCI image with the input marker, generated by `scripts/generate-oci-layout-fixture.mjs` from `testdata/oci-layout-source/`. `testdata/trivy-java-db-test.jar.base64`: a JAR with no package metadata. Provenance of both is in `testdata/OCI-FIXTURE.md`. |
| Build | The `launcher` stage of each engine Dockerfile copies `go.mod`, `main.go` and `main_test.go`, runs `go test ./...` and builds `/usr/local/bin/ai-security-scanner-engine-entrypoint` (`-trimpath`, empty build id), which is the image `ENTRYPOINT`. Semgrep and TruffleHog build with `golang:1.25.10-alpine`, the other four with `golang:1.26.3-alpine`; both images are digest-pinned. |
| Recorded in | `wrapper.launcher_sha256` (the SHA-256 of `main.go`) in all six plans. `scripts/validate-engine-catalog.mjs` requires it to equal the current file. |
| Publish workflow | `.github/workflows/engine-images-local-k8s.yml`, one matrix entry per engine |

## What it enforces

- **Arguments** (`run`). The command line must be exactly `--engine <id> --workspace /workspace --output /output`, with nothing positional. `supportedEngine` allows `semgrep`, `trufflehog`, `trivy`, `grype`, `kubescape` and `kube-bench`. Both paths must be real directories, not symlinks. `/workspace` must be mounted read-only: `requireReadOnlyWorkspace` reads the `statfs` read-only flag on Linux.
- **Input profile** (`loadInputProfile`, `validateEngineInputProfile`).
  - No `.ai-security-scanner-input.json` in the workspace means `repository_working_tree`. A marker must be a regular file of 2 to 4096 bytes of strict JSON (no unknown field, nothing trailing), with schema `ai-security-scanner.local-input/v1` and profile `iac_working_tree`, `container_image_oci_layout`, `kubernetes_manifests` or `kubernetes_node_snapshot`.
  - Allowed pairs: Semgrep and TruffleHog take repositories only; Trivy takes repository, IaC and OCI; Grype takes repository and OCI; Kubescape takes manifests; kube-bench takes the node snapshot. Any other pair fails with `engine <id> cannot consume local input profile <profile>`.
- **Offline inputs** (`verifyEngineInputs`, plus the release constants at the end of `main.go`). Checked before any scanner starts:
  - Semgrep's rule pack (`verifySemgrepRulePack`): the `RULES.sha256` digest, exactly 1603 listed `.yaml`/`.yml` files in strict order, each hash-checked, and no symlink or unlisted file.
  - Trivy's `trivy.db` and `metadata.json`, plus the Java DB pair except for OCI input; Grype's `vulnerability.db`; Kubescape's three framework files; kube-bench's node snapshot.
  - A mismatch fails with `immutable input <path> does not match its release digest`.
- **Invocation** (`planInvocation`, `planInvocations`, `execute`). No shell; the program path and arguments are constants. The environment is rebuilt from scratch: `HOME`, `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` under `/tmp/ai-security-scanner-*`, `LANG` and `LC_ALL` `C.UTF-8`, `NO_COLOR=1`, `PATH=/usr/local/bin:/usr/bin:/bin`, `TMPDIR=/tmp`, plus each engine's update and telemetry switches. The working directory is `/workspace`. Each pass has one hour; on timeout or SIGTERM the whole process group is killed.
- **Evidence** (`ensureOutputAbsent`, `validateEvidence`).
  - Every planned output must be absent before the first pass. Stderr is captured up to 8 MiB, and so is stdout unless it is the evidence; overflow fails the run, and a failure message carries the last 2048 characters.
  - The evidence must be a regular file of at most 512 MiB: one JSON value of at least 2 bytes, not `null`, with nothing after it. TruffleHog's is JSON Lines instead: every non-blank line an object, and an empty file is valid.
  - Accepted files are set to mode 0600. Any failure removes every planned output.
- **Refusal.** Prints `ai-security-scanner-engine-entrypoint: <reason>` and exits 126. The kube-bench image also installs the binary as `ps` and `stat`; under those names it answers from the recorded node snapshot instead (`runSnapshotPS`, `runSnapshotStat`; see `kube-bench.md`).

## Per-engine invocations

| Engine | Fixed command | Evidence in `/output` |
| --- | --- | --- |
| semgrep | `semgrep scan --json --config /opt/ai-security-scanner/semgrep/rules --metrics=off --disable-version-check --no-rewrite-rule-ids --oss-only --jobs 2 --max-memory 2048 --timeout 10 --timeout-threshold 3 --max-target-bytes 10000000 /workspace` | `semgrep.json` |
| trufflehog | `trufflehog filesystem /workspace --json --no-verification --no-verification-cache --no-update --concurrency 4`; stdout goes straight into the evidence file (`O_EXCL`, mode 0600) | `trufflehog.jsonl` |
| trivy | OCI input: `trivy image --input /workspace` with `--pkg-types os`. Repository and IaC input: `trivy filesystem` with `--pkg-types library`, then `trivy rootfs` with the same profile. All passes share the offline flags on the Trivy page. | `trivy.json`, plus `trivy-individual-packages.json` for working trees |
| grype | `grype dir:/workspace` (repository) or `grype oci-dir:/workspace` (OCI), with `--output json --file <evidence>` | `grype.json` |
| kubescape | `kubescape scan framework nsa /workspace` with the image's framework, controls and exceptions files, `--keep-local --submit=false` | `kubescape.json` |
| kube-bench | `kube-bench run --benchmark cis-1.11 --targets node` with the image's config and `--exit-code 0` | `kube-bench.json` |

## Host side

- **Container** (flags in `src-tauri/src/container_runtime.rs`, limits from `src-tauri/src/commands.rs`).
  - Security: `--read-only`, `--cap-drop=ALL`, `no-new-privileges`, the desktop user's uid and gid (65532 on Windows), and `--network none` (catalog `execution.network.mode` is `disabled`).
  - Resources: memory from `estimated_memory_mb`, 256 pids, a 512 MiB file-size ulimit, and `/tmp` as a `noexec` tmpfs sized from `estimated_disk_mb` (clamped to 16-4096 MB).
  - Mounts and limits: `/workspace` read-only, `/output` writable. The catalog `command` goes to the image entrypoint. The host stops the container after the catalog `timeout_seconds` (3600 s), which covers both Trivy passes together.
- **Snapshot** (`src-tauri/src/workspace_snapshot.rs`). The workspace is a copy of the selected working tree without any `.git` entry. Repository input honours root and nested `.gitignore` files but keeps tracked files, and ignored files whose names suggest secrets or configuration. The marker is written only for non-repository profiles, and a source that already contains one is refused. An IaC snapshot must contain a `.tf`, `.json`, `.yaml` or `.yml` file.
- **Exit handling** (`src-tauri/src/orchestrator.rs`). A non-zero exit fails the run before any adapter runs.
  - If the stderr tail holds `cannot consume local input profile` (`LOCAL_INPUT_PROFILE_REJECTION_MARKER` in `container_runtime.rs`), the failure code is `local_input_profile_unsupported`, which the report shows as Not tested (`src-tauri/src/beginner_report.rs`).
  - `tests/ci/local-input-profile-rejection-marker.test.mjs` keeps the Go message and the Rust constant in step.
- **Collection** (`collect_output_artifacts` in `src-tauri/src/artifact_store.rs`). Every regular file under `/output` becomes a raw artifact, so both Trivy files reach the adapter.

## Tests

- **Unit tests.** `main_test.go` has 16 tests, using temporary directories only, so the Dockerfiles need not copy `testdata/`. Among them:
  - `TestStaticPlansNeverUseShellNetworkOrUserArguments`, `TestSemgrepRulePackManifestRejectsTamperingAndUninventoriedFiles`;
  - `TestTrivyFilesystemProfilesUseLibraryPackagesAndKeepTheImmutableDatabaseReadOnly`, `TestTrivyOCIProfileDoesNotAddAWorkingTreePackagePass`, `TestGrypeRepositoryUsesTheUpstreamDirectoryCataloger`;
  - `TestEngineProfilesRejectCrossTypeExecution`, `TestInputMarkerIsStrictAndRepositoryDefaultsOnlyWhenAbsent`, `TestInvalidContractAndWritableWorkspaceFailClosed`, `TestSupportedEnginesAreExact`.
- **Workflow gate.** The `launcher-tests` job runs in `golang:1.26.3-alpine`. It requires an empty `gofmt -d main.go main_test.go` and a passing `go test ./...`, then regenerates the OCI fixture and fails on any `git diff` under `testdata/oci-layout` or `testdata/oci-layout-source`.
- **Image smoke.** Each publish job runs the image the way the desktop does over its smoke workspace. It checks JSON validity for every engine, plus content for Trivy and Grype. To replay it by hand: `docker run --rm --read-only --network none --cap-drop ALL --security-opt no-new-privileges:true --user "$(id -u):$(id -g)" --tmpfs /tmp:rw,nosuid,nodev,noexec,mode=1777,size=1024m --mount type=bind,src=<workspace>,dst=/workspace,readonly --mount type=bind,src=<output>,dst=/output <image>@<digest> --engine <id> --workspace /workspace --output /output`.

## Publishing

- **Triggers.** Pushes to `main` that touch `engines/images/local-launcher/**`, any of the six engine directories (each `plan.json` excepted), `scripts/generate-oci-layout-fixture.mjs` or `scripts/prepare-offline-engine-data.mjs`, and manual dispatch. Every run builds all six entries (`fail-fast: false`).
- **Plans track source, not images.** All six plans record `launcher_sha256` `ddd57759…`, the current `main.go`, but the images differ:
  - Semgrep `1.174.0-4` was published at 94af3e7 from the current launcher and pinned in b0c4ed4.
  - TruffleHog and Kubescape were published from 2641850, whose launcher hashes to `8ae5ab14…`.
  - Trivy and kube-bench were rebuilt at 9ee5257 from the launcher recorded then (`e5b1c32b…`) and pinned in 85f92b1.
  - The Grype pin has no build provenance (3990168).
- **Tag reuse.** The guard (`publicationPreflight` in `scripts/engine-image-evidence.mjs`) builds any tag that does not exist yet. An existing tag is reused only with a verifiable attestation and a plan, at the publishing commit, that binds that tag with the same recorded input hashes.
  - Today only Trivy and kube-bench pass. The Semgrep plan at 94af3e7 still binds `1.174.0-3`, the plans at 2641850 still bind the earlier `-2` tags, and the Grype image has no attestation.
  - Give Semgrep, TruffleHog, Kubescape and Grype new tags in any push that touches these paths, or their jobs fail.
- **Launcher changes.** A change to `main.go` changes every plan's `launcher_sha256` and needs new tags for all six images. `go.mod` has no plan digest (`directories_without_plans` in `engines/image-input-hash-policy.json`), and `main_test.go` and `testdata/` are excluded from the hash. The guard cannot see a change to those files alone, so advance the tags by hand.

## Lessons from real runs

- 2026-08-28: working-tree Trivy runs never matched lockfile dependencies -> every profile used `--pkg-types os` -> working trees use `--pkg-types library` (f50d967).
- 2026-09-09: one Trivy pass could not see both lockfile and JAR-only dependencies -> `filesystem` disables individual-package analyzers and `rootfs` disables lockfile analyzers -> working trees get a second `rootfs` pass, and the image embeds the Java DB (686e427).
- 2026-09-09: kube-bench ran a product-written six-check subset -> replaced by the unmodified CIS 1.11 node profile with the `ps`/`stat` replay (f6b6171; see `kube-bench.md`).
- 2026-09-19: a check the launcher refused for its input type was presented as a failure to retry, and the scan sat at Need attention -> the host could not tell that refusal from a crash -> the marker now maps to `local_input_profile_unsupported` and Not tested (d8db493).
- 2026-09-20: Grype reported 0 findings on a repository where Trivy reported 82 -> the pinned `0.117.0-3` image predated ef1c653, which allowed repository input -> re-pinned to `0.117.0-4` (3990168; see [Grype](grype.md)).
