# 掃描範圍

[English](scanning-scope.md) · [文件](README.zh-TW.md)

確認頁面就是執行界線。使用者確認後，網路掃描器只會收到畫面列出的精確目標與連接埠；本機掃描器只會收到選定來源的隔離副本。

## IT 環境

一個 IT 環境專案可以包含程式碼專案、網站與內部系統。執行計畫會把每個資產綁定到適用的檢查；引擎不會把其中一個資產的範圍擴大到其他相容資產。

每個內部系統是一個精確主機名稱或 IP 位址。預設 TCP 連接埠為 22、23、25、80、443、445、3389、5900、8080 與 8443；進階設定可替換成該主機最多 64 個精確連接埠。盤點範圍會維持盤點用途，直到個別系統被加入並確認。

## 網站或 API

網站快速設定會使用固定版本的 Nuclei automatic scan 檢查一個精確 `scheme://host:port` origin。輸入的 path 會保留作為參考；相符模板可以請求同一 origin 內的其他 path。

Nuclei 先執行上游技術辨識，再從固定的唯讀模板快照選擇適用的弱點與暴露檢查。這個設定不會登入、送出表單或 request body、跟隨重新導向、使用站外回呼、執行 headless 流程、上傳檔案、進行無界 fuzzing，或選用 exploit 與 denial-of-service 模板。

完成且沒有 finding 的結果會記錄 Nuclei 已完成的檢查與精確 origin。實際執行的模板由上游技術辨識與模板適用性決定。

## 專案資料夾

應用程式會建立有界的私密副本，並依適用情況執行以下上游檢查：

- 秘密內容，呈現時會遮蔽值；
- 危險程式碼模式；
- 已辨識 manifest 與套件中的弱點相依項目；
- 應用程式、部署、基礎設施與 Kubernetes 設定；
- 報告與匯出使用的元件清單。

建立副本時會依 repository ignore 規則排除產生內容、相依項目、建置、快取與版本控制目錄。`.env` 變體、私鑰、registry 或 authentication 設定、`*.tfvars` 等常見秘密來源檔案仍會交給秘密掃描器。

應用程式不會建置、執行、上傳、commit、push 或修改專案。

## 內部系統

通用內部系統設定會把已確認的精確主機與連接埠交給 Greenbone。固定版本的 Community Feed 提供目前有效、未淘汰且不需登入的遠端 `gather_info` 弱點測試；服務與產品辨識、先決條件、相依關係、嚴重度、證據及 remediation 均由 Greenbone 決定。

這個設定不使用憑證，並排除本機登入檢查、預設帳號、暴力嘗試、政策類別、替代連接埠掃描器，以及 attack、denial、destructive、kill-host 與 flood 類別。它不會加入鄰近主機或畫面未列出的連接埠。

開放連接埠與已辨識服務會放在**觀察到的服務—不是弱點**。只有上游弱點結果才會成為安全問題。

## 基礎設施、容器、Kubernetes 與雲端

基礎設施檔案與 Kubernetes manifest 會以選定內容進行掃描；匯出的容器映像會在不執行映像的情況下檢查。即時叢集與雲端路徑使用各自選定的資源與權限範圍。

雲端授權使用服務商官方瀏覽器流程或隔離的管理 bootstrap request。掃描憑證不會輸入一般應用程式密碼欄位。

## Localhost TCP 工具

Localhost TCP 工具會對 `127.0.0.1:9001` 進行一次不傳送內容的連線嘗試，結果為接受、拒絕或逾時。這不是弱點掃描。

## 資源設定

每個設定在執行前固定適用的速率、並行數、逾時、輸出、runtime 與取消限制。掃描器識別碼、嚴重度、證據與 remediation 保留上游定義；產品自己的優先排序與跨引擎整理在共用報告層進行。
