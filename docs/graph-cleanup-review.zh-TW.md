# Microsoft 365 清理 script 檢修紀錄

日期：2026-10-04。這輪處理掃描後撤權、異常恢復與操作說明；沒有發布版本，也沒有對真實租用戶執行撤權。

## 四份獨立檢查

實際呼叫兩份 `grok` CLI，模型指定 `grok-4.7`，分別檢查資源歸屬與中斷恢復；另呼叫兩份 `agy` CLI，模型指定 `claude-opus-5-5-high`，分別檢查完整流程與操作說明。四份審查均成功回傳。Grok 最初兩次因輸入截斷而失敗，拆成單一 script 後重跑成功；失敗紀錄也保留，沒有算成完成的審查。

審查使用程式碼與測試的快照，不會登入雲端。原始回覆、輸入、指定模型、執行結果與 SHA-256 存在本機 `.ai-security-scanner/reviews/2026-10-04-graph-cleanup/`，不包含真實雲端憑證。

## 已採納並驗證

| 問題 | 處理方式 |
| --- | --- |
| 設定還在建立資源，另一個清理程序就開始拆除。 | 設定與清理使用同一份紀錄的互斥鎖；同一目錄的設定也序列執行。衝突會在清理登入前停止。 |
| 等待較久後，Windows 的裝置代碼登入過期。 | 等待模式取得更新權杖，只留在記憶體；使用同一租用戶更新登入，期限限定為等待時間加 15 分鐘。Microsoft 拒絕更新時保持待處理，不重送結果未知的變更要求。 |
| 中文路徑、切換目錄後的相對路徑，以及 CLI 的 UTF-8 輸出讀錯。 | 以 PowerShell 的目前位置解析路徑，明確使用 UTF-8 讀取紀錄與 CLI 輸出。 |
| 列出授權時重新取得了管理權限，舊完成狀態卻讓下次清理直接跳過。 | 再次登入查詢前先標成需要重查；一般重跑已完成紀錄仍不重新登入。 |
| 清理中斷後，Microsoft 給同一身分建立另一個 GrantId。 | 保存選定授權的身分關係，指出新的 ID，要求明確選定後才移除，不把舊 ID 查不到當成新的授權也已移除。 |
| 打錯授權 ID，或修改紀錄缺少原本設定。 | 新選定的 ID 必須存在且屬於 Graph PowerShell；缺少修改前快照的紀錄在登入前拒絕。 |
| 服務身分建立成功，但回覆遺失，重試卻一直再建立。 | 建立時寫入此次操作的標記；失敗後查核標記，可以恢復同一筆建立紀錄，不只依應用程式 ID 採認既有資源。 |
| 共用設定在讀取後被別人修改，又遭舊資料覆蓋。 | 修改前重新比對原本讀到的欄位；發現差異就停止，不送出已知過時的修改。這不代表能跨不同電腦鎖住租用戶中的所有管理操作。 |
| 應用程式或服務身分已被改成其他用途。 | 先檢查建立標記、憑證、聯合身分憑證、對外提供的存取與角色等，再拆除。 |
| 預覽等了兩小時，或掃描程式已移除而永遠無法撤權。 | 預覽只查一次狀態；另提供明確的 `-RevokeNow`，讓操作者選擇跳過狀態與報告匯出。一般重試仍保留原掃描的檢查。 |
| 重跑設定沒有新增任何權限，清理卻說已撤除。 | 明確說明這份新紀錄沒有可撤除的新增內容，需使用最初建立權限的紀錄。 |
| 刪除要求成功，但服務商尚未同步顯示結果。 | 在同一登入中短暫重查，並以個別資源查詢核對過時的清單；無法確認仍保持待處理。 |

## 沒有直接照做的建議

- 不要求每次重跑已完成的紀錄都重新登入查雲端。這本身可能重新取得剛撤掉的 Graph PowerShell 管理授權；完成紀錄表示該次處理結果，不是日後永不變動的雲端保證。
- 不依應用程式名字猜測資源，也不因查不到結果就刪掉整個父資源。無法確認的建立要求保持待核對，避免擴大刪除範圍。
- 不要求掃描一定有至少一筆 engine run 才能收尾。產品允許未開始檢查就取消的終止結果；仍會驗證案件、掃描 ID、終止時間及所有存在的工作狀態。
- 沒有加入新的「刪除空白授權」確認流程。操作者已明確選定 GrantId 及要移除的兩項管理權限；若沒有其他權限，移除那筆空授權不增加撤除範圍。
- 沒有依未重現的 Windows 單元素 JSON 陣列推論更換序列化程式。Windows PowerShell 5.1 的真機驗證仍列為未完成。
- `Connect-MgGraph -AccessToken` 不接受 `-ContextScope`，因此沒有直接加入該參數；一般互動登入維持 `Process`。[Microsoft 參數說明](https://learn.microsoft.com/en-us/powershell/module/microsoft.graph.authentication/connect-mggraph?view=graph-powershell-1.0)。

## 證據與界線

完整設定／清理測試 41 項通過，另增加的授權 ID 更換後重試測試也通過，合計 42 項；設定指引的 10 項檢查亦通過。這些是本機 PowerShell 7 配合模擬 Graph 的流程驗證，涵蓋成功、失敗、取消、過期、並行、部分建立、回覆遺失、權限保留、報告匯出與重試。不是 Microsoft 真實租用戶的驗收，也不是 Windows PowerShell 5.1 真機測試。

清理 JSON 沒有簽章，應只使用自己保存的原始紀錄。欄位驗證與雲端建立標記可擋下部分錯誤與錯配，但不能把任意修改過的歷史快照當成可信的資源歸屬證明。第一次登入已經造成的 Graph PowerShell 同意授權也沒有登入前快照，因此仍需明確選定授權 ID。

若建立要求回覆遺失、後續始終查不到對應資源，會留下待核對紀錄。突然斷電造成的檔案系統狀態、跨電腦同時修改共用應用程式，也不在此次測試已證明的範圍內。建議使用每次掃描專用的 `-Temporary` 應用程式，避免共用授權被另一份清理紀錄撤除。

舊 AWS／Azure／Microsoft 365 權限尚未實際撤除，仍需原始設定位置、可核對的資源紀錄與服務商登入。GCP／GAS 真實掃描範圍與實測也沒有因這輪 Graph 檢修而完成。
