## 目前結論

報告與必要證據應該留下；這次掃描才建立的臨時登入資料、容器、網路與工作檔，應在不再使用時清除。掃描失敗、取消或程式重開後，也要接續清理。不能等使用者按下「匯出」，才開始處理臨時資源。

目前容器和臨時憑證已有自動清理。Microsoft 365 另已補上[清理 script](../cloud-setup/README.md)，可以等待指定掃描結束、儲存 HTML 報告，再撤除新設定紀錄中的項目；Graph PowerShell 的管理授權可依明確指定的授權 ID 一起收回。這是需先啟動的 PowerShell 輔助流程，尚未成為桌面程式的預設動作；登入過期或程序中斷時可能需要重試。

舊 Microsoft 365 設定已另外完成兩筆指定授權的實際撤除與查驗，詳見下方紀錄。舊 AWS 權限、Azure 訂閱權限及保留的應用程式註冊，仍不能說已清除。

## 修正了哪個自動清理缺口？

臨時憑證檔原本要等寫入、權限設定和檔案檢查全部成功，才會交給自動清理程式管理。如果中途出錯，可能留下已建立的檔案。

現在檔案一建立成功，就由清理保護接手；後續失敗會嘗試清掉這個檔案。Unix 平台也會從建立當下就限制為只有檔案擁有者可讀寫。已存在的同名檔案不會被覆寫或刪除。

[實作與回歸測試](../src-tauri/src/container_runtime.rs)驗證了「建立後檢查失敗不留檔」和「同名既有檔案不受影響」。這是局部修正，不代表所有檔案系統錯誤、停電或雲端撤權都已解決。

## AWS 與 Azure 為什麼還不能說清乾淨？

本機已找到 AWS 和 Microsoft 365 的舊掃描紀錄。對這些案件執行產品的清理查詢，沒有待處理的容器清理紀錄，也沒有可用的雲端臨時權限撤除清單。**沒有清理清單，不代表雲端沒有權限殘留。** 在已檢查的資料目錄中，尚未找到可核對的 Azure 訂用帳戶實測紀錄。

原本的 [AWS 設定 script](../cloud-setup/aws-read-only.sh)會建立或沿用 `SecurityAudit` 權限集並指派使用者；新版另有 `--temporary` 模式，建立專用權限集、保存清理紀錄，並由配套程式撤除。[Microsoft 365 設定 script](../cloud-setup/microsoft365-read-only.ps1)也已保存建立前後的紀錄。舊版匯出的設定檔只記錄連線方式，無法補出每一筆權限究竟是當時新增，還是早已存在。因此不能按名字把整個權限集、使用者或應用程式刪掉。

此外，結束登入不等於撤掉所有已取得的存取。AWS 說明 IAM 角色工作階段可在入口網站登出後持續到期；撤除程序需要分別確認權限指派與仍有效的工作階段。[AWS 官方說明](https://docs.aws.amazon.com/singlesignon/latest/userguide/authconcept.html)。Azure 撤除角色指派則需要對應的刪除權限，唯讀掃描身分不具備這項能力。[Microsoft 官方說明](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-remove)。

使用者已說明，這次提到的 Azure 是上述 Microsoft 365／Graph 環境，AWS 舊測試環境暫不需要清理。因此本次不再擴大雲端盤點，只補 AWS 設定與清理程式。沒有把未操作的 AWS 或 Azure 訂閱寫成已清乾淨。

## 自動清理應補齊什麼？

以下是跨雲端的收尾原則。Microsoft 365 與 AWS 專用存取流程已實作建立紀錄、等待指定掃描、匯出報告、依紀錄撤除及查驗。AWS 的等待模式需與掃描資料在同一台 Linux 電腦；CloudShell 無法直接讀取 Windows 案件。Azure 訂閱撤權、桌面預設收尾與關機後自動接續仍未補齊：

1. **建立前先記帳。** 每次設定保存不含密鑰的紀錄：是哪個帳號、哪次掃描、準備建立什麼。建立成功後保存服務商回傳的確切 ID，並區分新增與沿用。
2. **結果存好就收尾。** 掃描停止聯絡目標、結果和報告所需證據存好後，清掉本次的臨時登入資料、容器、網路與無保存用途的工作檔。成功、失敗、取消都走這條路。
3. **雲端權限另有期限。** 不把管理員權限長期留在掃描器裡。Microsoft 365 清理 script 使用獨立的管理員登入工作階段，不把權杖存進清理紀錄或交給掃描器。等待期間會嘗試在記憶體中更新登入；Microsoft 若要求重新驗證，需重新登入。AWS 使用管理員已登入的官方 CLI；掃描專用角色的工作階段上限為一小時，撤權不代表既有工作階段立即失效。
4. **失敗就保留待辦紀錄。** 顯示「報告已保存，權限尚未撤除」等實際狀態。程式重開後可以重試，不把「已送出刪除要求」寫成「已刪除」。
5. **確認真的結束。** 向服務商確認權限／資源狀態，另外記錄尚有效的工作階段或等待到期的期限。不能只以登入過期判定全部完成。

驗收需涵蓋正常完成、取消、程序中斷、清理失敗後重試、服務商已刪除，以及共享資源不被誤刪。清理後仍必須能重新開啟與匯出報告。
