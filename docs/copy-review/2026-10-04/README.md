# README、網站與報告文案比較

這次改寫是給使用 AI 工作、但不熟資安工程的人看：先說能查什麼、結果代表什麼、下一步怎麼做。中英文都要自然、準確，技術資料留給需要的人展開查閱。

四份版本使用相同的原始中英文 README、網站文字及產品事實限制。三份外部模型原稿由本機已登入的 CLI 實際產生，沒有以其他模型代寫，也沒有交付真實客戶報告、帳號資料或憑證。

| 版本 | 產生方式 | 我的評讀 |
| --- | --- | --- |
| [Codex 版本](codex.md) | 本次主編寫版本 | 開頭最短，直接交代用途和下一步。已套用到工作目錄中的 README、網站與部分報告文字。 |
| [Grok 4.7 原稿](grok-4.7.md) | `grok --model grok-4.7` | 資訊保留多、限制交代完整，但「上游工具」「執行界線」等詞仍偏工程語言，篇幅也較長。 |
| [Opus 5.5 原稿](opus-5.5.md) | `agy --model claude-opus-5-5-high` | 語句較像對人說話，步驟具體；需要再縮短篇幅，並避免讓「不修改任何東西」涵蓋會建立權限的雲端設定流程。 |
| [Gemini 3.8 Flash 原稿](gemini-3.8-flash.md) | `agy --model gemini-3.8-flash-high` | 完整但仍偏公文。原稿把內部系統能力寫成連線與盤點，漏了適用的安全檢查；「無害 HTTP 請求」也太絕對，不應直接採用。 |

CLI 的執行結果記錄在 [generation.json](generation.json)。上述原稿維持原樣，方便比較；裡面的相對連結是按預定貼回 README 的位置撰寫，並非這個比較資料夾的導覽連結。

## 已採用的寫法

> 檢查你的程式碼、網站與公司系統，把需要注意的安全問題整理成一份報告。你會知道哪裡有問題、為什麼重要，以及接下來可以怎麼做。

不必每段都重講一次限制。需要操作決定的限制，放在對應步驟；檢查沒有完成，直接說沒有完成；原始規則、版本與證據則留在技術細節。

## 保留的事實

- 掃描必須在桌面程式開始、暫停與繼續。AI 助手可以協助設定、解讀與匯出，不能自行啟動掃描。
- 「沒有發現問題」只適用於已完成的檢查。盤點和開放連接埠不算漏洞。
- AWS、Azure、GCP 目前只涵蓋部分身分與權限檢查，不能寫成完整雲端稽核。
- 設定 script 建立的雲端權限，目前不會在掃描後自動撤回。
- 範例報告是模擬資料。這次保留原有 v0.4.0 範例的報告本體，更新的是範例說明及工具用途附錄；新的報告摘要文字則在程式中另行驗證。
